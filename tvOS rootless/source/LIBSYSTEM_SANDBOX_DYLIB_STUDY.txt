§1 EXECUTIVE SUMMARY
================================================================================

libsystem_sandbox.dylib is a **thin MIG client** for the kernel `Sandbox`
subsystem. It does **NOT**:

  - read or write mac_label slots (no `mac_label` string/symbol in entire binary)
  - implement unsandbox / slot-1 clear (Dopamine does that via kwrite in app)
  - contain `com.apple.sandbox.executable` (that class string lives in kernel +
    jailbreak code — passed as raw C string to issue APIs)
  - export `sandbox_apply` (lives in **libsandbox.1.dylib**, dlopen'd at runtime)

Every permission decision for op 16/129 happens in **kernel** after MIG dispatch.
This dylib only packages arguments and calls `__sandbox_ms("Sandbox", routine, ...)`.

For tvrootshell build102.3.3 wall:
  App/helper calls `sandbox_extension_consume(token)` → MIG **routine 6**
  → kernel `sub_55106C` → needs live slot-0 profile via `532C68/532930`.
  Missing/incorrect consume on the **executing process profile** = op 16 deny
  on dyld mmap — exactly what device logs show.

Conclusion (closes KERNEL doc O4 partially):
  Dopamine `mac_label_set(label, 1, -1)` is **NOT implemented or mirrored** in

§5 EXTENSION ISSUE PATH (userspace → kernel)
================================================================================

5.1 Public wrappers

  sandbox_extension_issue_file(class, path, flags)
    → __sandbox_extension_issue(class, **0**, path, flags & 0xFFFCFFFF, 0, 0)
    @ 0x1801B2550

  **KERNEL CLOSED (build102.4 device):** flags & 0x4 (PREFIXMATCH) + subtype 0
  → kernel 550690 @ 0xFFFFFFF0065508A4 returns **45 EOPNOTSUPP** before profile
  check. Do NOT use PREFIXMATCH with issue_file. Dopamine uses flags **0**.
  See BUILD102.4_DEVICE_FAILURE_IDA_TRACE.txt §3.

  sandbox_extension_issue_file_to_process(class, path, flags, audit_token)
    → __sandbox_extension_issue(class, 0, path, flags | **0x30000**, 
                                token.pid @ +0x14, token.version @ +0x1C)
    @ 0x1801B256C

  Flags 0x30000 = 0x10000 | 0x20000:
    Matches kernel 55106C consume checks:
      (flags & 0x10000) → must match issuing pid
      (flags & 0x20000) → must match pid version
    Dopamine launchdhook uses issue_file_to_process for per-process tokens.

5.2 Core issuer __sandbox_extension_issue @ 0x1801B3470

  1. malloc(2048) for token string buffer
  2. If flags bit 0: snprintf "invalid" (error path)
  3. Pack args [class, subtype=0, path, flags, buf, pid, pidversion]
  4. __sandbox_ms("Sandbox", **5**, &args)   ← MIG routine **5** = ISSUE
  5. On failure: free buffer, preserve errno

  Kernel target: sub_550690 (issue) → sub_532C68 → 532930(slot0)

5.3 Dopamine launchdhook mapping (reference)

  systemwide_process_checkin issues:
    sandbox_extension_issue_file_to_process("com.apple.app-sandbox.read", JBROOT, ...)
    sandbox_extension_issue_file_to_process("com.apple.sandbox.executable", JBROOT, ...)
  Returns pipe-separated tokens → systemhook sandbox_extension_consume per token.

  tvrootshell build97 uses sandbox_extension_issue_file (self-issue, no audit_token)
  from app context — different flags path (no 0x30000 unless explicitly set).

§6 EXTENSION CONSUME PATH (userspace → kernel) — CRITICAL FOR build102.3.3
================================================================================

sandbox_extension_consume @ 0x1801B2728:

  1. sub_1801B46A8(token, "invalid") — validate token prefix/Magic
  2. sub_1801B46CC(token) — token length helper (strlen variant)
  3. Build MIG args on stack:
       [0] = token pointer
       [1] = length + 1
       [2] = &handle_out (int64)
  4. __sandbox_ms("Sandbox", **6**, args)   ← MIG routine **6** = CONSUME
  5. Return handle_out, or 0 if validate fail, or -1 if MIG error

  Disasm proof:
    1801B2774  MOV W1, #6
    1801B2778  BL  __sandbox_ms

  Kernel target: sub_55106C @ FFFFFFF00655106C
    5510E4  BL 532C68(proc)     ; proc → profile from slot 0
    5510E8  CBZ X0 → handle 0    ; build96 device failure

  **Return value semantics:**
    > 0  : extension handle (success)
    0    : token invalid OR profile NULL (kernel zero copyout)
    -1   : MIG/syscall error (errno set)

  sandbox_consume_extension @ 1801B37B8:
    wrapper: consume == -1 → return -1, else 0

  sandbox_init_with_extensions @ 1801B3548:
    For each path in array:
      issue_file(READ_CLASS, path) → consume each token
    Then sandbox_init(profile)
    **Same pattern Dopamine wants** — issue + consume before spawn.

§7 SANDBOX CHECK PATH
================================================================================

sandbox_check(pid, operation, flags, ...) @ 1801B1A88
  → sandbox_operation_fixup (normalize op name string)
  → sandbox_check_common
  → __sandbox_ms("Sandbox", **2**, &args)
  → returns 0 allow, 1 deny, -1 error

sandbox_check_common @ 1801B1B5C:
  Maps check type flags (0x40000000 NO_REPORT, etc.) into arg bundle
  Switch on check subtype → kernel opcode numbers (1-50, 241, …)

Used by Dopamine systemhook:
  sandbox_check(getpid(), "process-fork", SANDBOX_CHECK_NO_REPORT, NULL)
  to decide if forkfix.dylib is needed.

For tvrootshell: sandbox_check from app on "process-exec*" is a **diagnostic**
only — real deny is kernel-side with richer context than userspace check.

================================================================================
§8 SANDBOX INIT / PROFILE APPLY (libsandbox.1.dylib path)
================================================================================

sandbox_init_with_parameters @ 1801B1688:

  1. dlopen("/usr/lib/libsandbox.1.dylib")
  2. dlsym sandbox_create_params / sandbox_set_param / sandbox_free_params
  3. By flags:
     flags=0 → dlsym sandbox_compile_string → sandbox_apply
     flags=1 → sandbox_compile_named
     flags=2 → __sandbox_ms("Sandbox", 1, ...) direct compile
     flags=3 → sandbox_compile_file → sandbox_apply
  4. sandbox_apply(profile) installs Seatbelt profile on **current process**
     (creates/updates slot-0 profile object in kernel)

This is how container profiles get attached — separate from extension consume.
TrollStore app already has a container profile in slot 0 (device logs).

systemhook hooks sandbox_apply in libsandbox.1.dylib to inject extension
consumes when profile is applied to child processes.

§12 WHAT tvrootshell NEEDS (study conclusion — still no build)
================================================================================

From libsystem_sandbox + kernel IDA together:

REQUIRED (matches Dopamine L3):
  1. sandbox_extension_issue_file (or issue_to_process) for:
       com.apple.app-sandbox.read
       com.apple.app-sandbox.read-write
       com.apple.sandbox.executable   ← string from jailbreak code, not dylib
     on prefix /private/var/jb
  2. sandbox_extension_consume on **the process that will exec/map** (helper
     or child), returning handle != 0
  3. slot 0 profile must remain valid through consume (build97 preserve — do
     NOT clear slot 0)

NOT SUFFICIENT:
  - mac_label slot 1 kwrite (not in this API; kernel ignores slot1 anyway)
  - trustcache alone (proven 102.3.3)
  - persona-root uid 0 alone (proven build93)
  - sandbox_check userspace probe

OPTIONAL / Dopamine-full (higher scope):
  - libsandbox.1.dylib sandbox_apply hook (systemhook) for auto-consume in children
  - launchdhook issue_file_to_process with audit_token (needs launchd inject)
  - sandbox_init_with_extensions pattern @ 1801B3548 (issue+consume array then init)
