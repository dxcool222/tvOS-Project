§3 IDA — ISSUE vs CONSUME ASYMMETRY (WHY ISSUE OK + CONSUME FAIL COEXIST)
================================================================================

Both use same sandbox sysctl dispatch @ 5FF124 (loads ucred → 534E04 arg0).

**ISSUE (550690, W1=5):**
  5509C4  BL  532C68
  5509CC  CBZ W22, loc_550A18    ; W22=extension type from userspace
  For sandbox_extension_issue_file → type **0 (file)** → **always bypass**
  NULL profile check @ 5509E4.
  550CD4 can run with profile=NULL via 541068 fallback @ 540F44 op 14.
  → Token string minted even when 532C68 returns NULL.

**CONSUME (55106C, W1=6):**
  5510E4  BL  532C68
  5510E8  CBZ X0, loc_55113C      ; **NO bypass** — NULL → handle=0 copyout
  Token parse / HMAC / 54FAF0 never reached when profile NULL.

Device signature handle=0 errno=0 = **only** 55113C path (§41.3 closed).

§4 ROOT CAUSE — 5FF124 DISPATCH BUG (IDA MCP VERIFIED 2026-06-19)
================================================================================

Site: 0xFFFFFFF0075FF124  (__TEXT_EXEC sandbox sysctl path)

MCP disasm:
  5FF120  BL  _vfs_context_current_0
  5FF124  LDR X0, [X0,#8]          ; bytes 0xF9400400
  5FF140  BL  sub_83C4B0            ; mac_policy_iterate → 534E04

vfs_context layout (CLOSED):
  +0x8  = ucred    ← 5FF124 loads THIS
  +0x10 = proc     ← _vfs_context_proc / _current_proc use THIS

534E04 sets X19 = arg0 (ucred kptr) for all sandbox opcodes including consume:
  535258  B 55106C
  551090  MOV X21, X0               ; X21 = ucred mistaken for proc
  5510E4  BL 532C68(X21)

532C68 expects proc_t:
  532C78  BL kauth_cred_proc_ref(proc)
  _proc_ucred reads [proc+0x18] proc_ro → [+0x20] ucred
  Feeding ucred kptr as proc → garbage proc_ro → Exit A @ 532C8C → NULL

build101 device (pid 236):
  proc_find_eq_ctx_proc=1
  mirror_532C68(real proc) = NONE (valid profile)
  mirror_532C68(ucred as proc) = Exit A
  consume handle=0 errno=0

**Semantic fix (NOT device-tested):**
  5FF124: 0xF9400400  LDR X0,[X0,#8]
       → 0xF9400810  LDR X0,[X0,#0x10]

**KFD write to 5FF124: CLOSED NO**
  Segment __TEXT_EXEC perm 0x5 (RX). Same class as prior sandbox __text patch panics.
  See mirror-trace.txt §24.2–§24.4.

§5 DOPAMINE iOS — CORRECTED INTERPRETATION
================================================================================

Dopamine launchdhook issues tokens via issue_file_to_process(flags=0) because:
  - Central issuer for **every child** via systemhook check-in
  - Pipe-separated multi-path grants in one checkin
  - NOT because sideloaded apps cannot call issue_file themselves

On **tvOS 16.5 j105a**, even Dopamine's systemhook consume path would hit the
same 55106C → 5FF124 bug unless kernel dispatch is fixed or iOS kernel differs
(O6 — not compared in IDA yet).

Dopamine still needed for tvrootshell long-term:
  Layer 4 child injection (dash won't inherit ext without 533304 + profile+8)
  Layer 6 persistence (out of scope for smoke)
